# Mem0 与 EverOS 选型说明（通俗版）

> 本文依据现有测试结果和 Agent 自动评估撰写，尚未经人工复核。它回答第一版产品应优先改造哪套框架；上线仍需修复缺陷并补做验证。

## 先说结论

**如果第一版要支持按用户、业务域和项目查找记忆，追溯到原始消息，直接录入已确认的经验，并接入 Email Agent，优先推进 Mem0。** 它已具备这些功能的主要路径，需要集中修复写入时误跳过记忆等问题。EverOS 保留为备选：它整理对话和记录事件变化的方式有优势，但当前还要补搜索索引、原始消息来源和直接录入等基础能力。

这个选择是**研发路线的优先级**，不是上线许可。Mem0 当前会静默漏存部分记忆；这个问题修好并复测前，不适合投入真实业务。

## 两套框架的思路

- **Mem0 像建立“事实卡片”**：从对话中提取短记忆，给它们附上用户、项目等信息；查询时按这些信息筛选，再找相关卡片。它适合快速找出某条规则或偏好，也便于把结果关联回原始消息。
- **EverOS 像整理“事件记录”**：把对话写成带时间的事件文本，再建立搜索索引供查询。它更容易保留一件事如何变化的上下文，例如“先设计、后开发、再联调”。事件文本保存下来之后，搜索索引还必须完整，查询才能找到它。

这里的**“隔离”**是指一个项目或业务域的记忆，不能被无权访问的项目或业务域读到；**“逐消息来源”**是指答案能够指出它依据的是对话中的哪一条原始消息，而不只是整段会话。

## 主要差距

| 关心的问题 | Mem0 当前表现 | EverOS 当前表现 |
|---|---|---|
| 找到需要的记忆 | 已有可用的语义搜索；按项目等条件读取时，隔离测试通过 | 能返回相关内容，但搜索索引有覆盖问题：原文仍在，查询却可能找不到 |
| 把记忆写进去 | 对相似内容会去重；去重没有正确区分项目等范围，可能把本该保存的记忆悄悄跳过 | 本轮受支持的对话写入未观察到提取遗漏；会保存事件原文，但部分中文内容被写成英文 |
| 解释答案从何而来 | 已验证可保存并返回具体消息编号 | 目前只能追到整段会话，无法稳定指向具体消息 |
| 直接保存一条已确认的规则或案例 | 已有可用入口 | 尚无对应的公开写入能力 |
| 处理“过去是什么、现在是什么” | 曾把多个历史阶段都当作“当前”，还出现过日期写错 | 事件有时间顺序，能更好保留变化脉络；按指定时间点回答仍未达标 |
| 接入 Email Agent | 本次三个任务按回答含义均完成 | 本次三个任务完成两个；另一个任务需要的项目记忆未被查到 |

## 各自的长处和问题

### Mem0

**长处**：搜索、按范围读取、回溯具体消息、直接录入规则，以及 Email Agent 接入，都已有实测可用的路径。因此第一版要补的基础接口较少。

**最严重的问题是写入范围混淆。** 例如，项目 A 和项目 B 各有一条意思相近的记忆，系统可能认为 B 的内容已经存在，便跳过写入；随后在 B 中也查不到它。测试中多次出现这种“没有报错，但记忆没存进去”的情况，且已在框架原生写入流程中复现。它会直接影响业务可信度，必须先修。

此外，“对外发送前须先让我确认”这类重要指令曾被稳定漏提取；中文记忆目前依赖额外的语言配置来保持中文；相近测试重复运行时也出现写入结果变化。涉及历史状态和准确日期的回答仍有错误。

### EverOS

**长处**：在本轮受支持的对话写入中，没有观察到 Mem0 那样的提取遗漏。对“只是提问”“明确否认”“转述他人”等语气，它保存的内容也较忠实；带时间的事件记录便于描述事情的先后变化。

**最严重的问题是搜索索引可能互相覆盖。** 同一用户在不同项目写入事件时，索引可能把先写的项目记录覆盖。原始事件文本还在，但搜索找不到。Email Agent 的一个任务就出现了“项目记忆在原文里，回答时却没有取回”的现象；该任务表现与索引问题一致，具体因果还需在修复后回归确认。

此外，查询结果缺少具体消息来源；无法直接录入一条已确认的规则或案例；部分中文对话被整理成英文事件，影响中文查询。按指定时间点查历史状态的整套要求，本轮也没有通过。

## 选择依据与边界

| 你的第一优先事项 | 当前建议 | 必须满足的前提 |
|---|---|---|
| 尽快做出可按项目检索、可追溯原消息、可直接录入规则的第一版 | 优先改造 Mem0 | 修复跨范围去重造成的漏存；验证重要指令能稳定保存；把中文配置纳入产品；对失败案例重测 |
| 更看重对话细节的保留和事件先后变化，且能接受较多基础改造 | 继续评估 EverOS | 修复并迁移索引；补具体消息来源和直接录入；治理中文写入；重新验证 Email Agent |
| 必须准确回答“某天或某时段，当时有效的状态是什么” | 暂不确定主选 | 两套框架都需要补完整的按时间查询能力，并针对该要求重新测试 |
| 近期直接上线 | 暂不建议任何一套 | 先完成上述阻塞项，以及尚未做的可靠性、恢复和容量验证 |

本轮完整测试中，Mem0 在两次运行里各通过 **32/40**，EverOS 各通过 **8/40**；Email Agent 按回答含义分别完成 **3/3** 和 **2/3** 个任务。这些数字统计的是**整套业务要求**，包含来源、写入方式、语言和隔离等条件。EverOS 有不少案例仅因缺少具体消息来源或不支持直接录入而失败；它的 8 个通过项均是负例或隔离例。**8/40 不能解读为“只有 8 次找对了内容”，也不能证明正向检索已达标。**这些语义结论尚未经人工复核，可靠性与恢复验证也未完成。
