# 选型结论

面向非技术读者的说明见[通俗版选型说明](selection_decision_explained.md)。

> **状态：Agent 自动评估的暂定结论，未经过人工复核。**
> 本文综合 8 份 Agent 语义评估与真实模型调用产物；原始机械状态保留在 artifacts 中。自动语义终判修正了 Mem0 full 的 N04（R0）和 N03（R1），但不改写原始运行结果。

## 当前结论

**推荐 Mem0 为 MVP 主选候选（有条件），EverOS 保留备选资格。**

两候选均**未无改造达标**：Mem0 full 自动语义终判双轨各 32/40、decision 各 9/12；EverOS full 双轨各 8/40、decision 各 4/12。Mem0 的 full 失败包括写路径去重越界 5 例、F04 提取遗漏，以及 C05/T02 时间与状态表达问题。EverOS 的失败覆盖索引完整性、中文语言合规、`direct_record` 契约与逐消息来源。上述通过率衡量整套业务要求，不能直接当作纯语义召回率：EverOS R0 有 16 例仅因来源检查失败，另有 6 例写入契约不支持；8 个通过项均为负例或隔离例，其中 N01～N05 的即时 0 hits 受索引可见性盲区影响。

## 判定基础

### 效果对比（Agent 自动语义终判口径）

| 维度 | Mem0 | EverOS |
|---|---|---|
| decision（12 例 × R0/R1） | 9 PASS / 3 FAIL，双轨一致 | 4 PASS / 8 FAIL，双轨一致 |
| full（40 例 × R0/R1） | 32 PASS / 8 FAIL，双轨一致 | 8 PASS / 32 FAIL，双轨一致 |
| P-native probe（6 例，复用面证据） | 2 FAIL（D03/T01 写 EMPTY）+ 4 项 hits 正常 | 5 FAIL + 1 UNSUPPORTED |
| Email Agent 端到端（按回答语义判定） | 3/3 任务；严格 token 检查为 5/6 个 M1/M2 回答 | 2/3 任务；严格 token 检查为 3/6 个 M1/M2 回答，A 任务 M1/M2 未取回 P1 决策 |

### R0/R1 对比（外置 rerank 是否构成差异）

- **Mem0**：修正 N04 的主语误判与 N03 的否定子串误判后，R0/R1 的 8 个终判 FAIL 案例相同。去重越界与 F04 漏提取在双轨均出现。
- **EverOS**：R0/R1 的 32 个终判 FAIL 案例相同；英文 episode 在 R1 的跨语言 rerank 分数很低（约 0.001～0.007）。
- **证据边界**：R0/R1 是独立写入和提取的 run，Mem0 的 N01/N03/U01-w1 等写入结果也发生翻转。因此相同或不同的终判集合都不能单独证明 rerank 的因果效果；若需量化 rerank 增益，应固定同一份已写入记忆后只切换检索轨道。
- full 的同候选 R0/R1 运行时间发生重叠（见各 `manifest.json`），与 runbook 的串行要求不一致。产物未出现 BLOCKED/TIMEOUT，但共享模型端点可能发生资源竞争；本轮运行耗时不用于候选性能排名。

### Mem0 阻塞缺陷（产品化前必须处理）

1. **写路径去重越界**：推理去重仅按 user_id、无视 metadata 边界，跨案例静默抑制写入且命名空间内永不可检索。证据：full D01/D03/D04/P02/T01 双轨 FAIL；decision D03/C02/T01；probe 的 D03/T01 再现空写入。源码与运行证据共同指向 mem0 核心 add 流程；静默丢数据，产品不可接受。
2. **F04 提取遗漏**：「对外发送须确认」指令类偏好双轨稳定漏提取。
3. **写路径非确定性**：temp=0 下 N01/N03/U01-w1 双轨翻转，无案例级复现性。
4. **原生中文提取缺陷**：开箱将中文记忆改写为英文，当前依赖 bench 披露的 custom_instructions 对齐 shim；锁定版无完整提取提示词替换口。
5. **时间与状态表达**：C05 返回三个均称“当前”的阶段，T02 将 9 月 14 日下午写成 9 月 15 日下午；若 MVP 需要 as-of 或精确有效期，必须单独补齐。

### EverOS 阻塞缺陷

1. **LanceDB 索引主键 `{user}_ep_{date}_{seq}` 不含空间成分**：同 session 多空间写入互相覆盖索引行（markdown 事实源完好）。full D01/D04/P02 有直接证据；Email 任务 A 的 P1 记忆在 markdown 中存在，但 M1/M2 检索只返回 shared 空间内容，符合该缺陷表现。probe D03/P01 的 0 hits 是相关风险信号，具体机制仍需单独确认。
2. **语言合规违规**：默认提示词强制语言一致，但共享 LLM 对简短输入违规产英文 episode（U01/C01/C02/T01/C05/T02 渗漏面），中文业务召回不稳定。
3. **direct_record 无契约**：E01 UNSUPPORTED（decision 双轨 + probe 一致）。
4. **逐消息来源缺失**：搜索 DTO 仅 session 级，F05 双轨 FAIL（来源缺失）。

### EverOS 相对优势（保留备选资格的理由）

- full 中受支持的 conversation 写入**未观察到提取遗漏**；已返回内容的负例/假设/否认/第三方引述框架忠实（疑问存为「U1询问…」、否认存为「U1否认…」）；Mem0 对应维度有 F04 稳定遗漏。
- episode 带时间戳演进，C05（版本链）forbidden 未出现（Mem0 三 hit 平铺、forbidden 出现）→ 时间感知的机制基础更好（但 T01~T05 仍 FAIL，as-of 两候选都需自建）。
- episode 追加式写入无语义去重，免疫 Mem0 式跨案例串扰。

## 决策条件与边界

- **若 MVP 范围 = 检索 + 读隔离 + 逐消息来源 + direct_record + Agent 接入**：Mem0 路线可优先推进，但上线前至少要修复去重作用域、验证 F04 类重要指令可稳定提取，并将语言对齐配置产品化。EverOS 路线需先完成索引主键改造及迁移、来源 DTO 扩展、新增写入契约和中文输出治理；工作量与风险更高（见 gaps_and_effort.md）。
- **若业务权重偏向提取忠实/时间演进**：EverOS 在该两维实测更优，可作为二期候选，前提是主键与语言缺陷修复验证通过。
- **Email Agent 的词面检查**：C 任务 M1 的检索上下文均含“转人工”，回答分别使用“转为人工处理”“转由人工处理”，语义满足任务要求，但不含精确子串“转人工”；这是当前 token 检查的误报，不能归为预取注入缺失。
- 本结论不覆盖可靠性/恢复维度（reliability 运行未执行）。

## 下一轮自动验证

1. 用脚本核对每份评审的案例终判、汇总表及结论报告统计；保留机械状态与语义终判两列，避免改写原始产物。
2. 在修复 Mem0 去重作用域、EverOS 索引主键后，针对已失败案例与 Email 任务 A 重跑回归；对需要因果比较的 rerank，固定写入结果后再测。
3. 补可靠性、恢复和容量验证后，才能将 MVP 技术选择推进为上线结论；现有人日区间只是 Agent 规划估计。
